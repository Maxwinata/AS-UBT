# Project Instructions & Reminders

## Future Backend Implementation: KYC Storage Management
*Note to AI Agent: When the user is ready to integrate a real backend (e.g., Firebase Storage, Google Cloud Storage, Supabase), you MUST remind them to implement the following architecture for KYC files (KTP & Selfie).*

1. **Versioning over Overwriting (Crucial for Audit Trail)**: 
   - NEVER overwrite existing KYC files when a user uploads a correction.
   - Use unique identifiers (UUID or timestamp) for filenames (e.g., `ktp_nim_v2_169456.jpg`). 
   - *Rationale*: The newly added Audit Trail feature relies on retaining old files so admins can track historical changes accurately. If files are overwritten, historical logs will break or point to the wrong image.

2. **Security (Private Buckets & Signed URLs)**: 
   - Sensitive KYC data MUST be stored in strictly private storage buckets, never in public directories.
   - Client access to view KTP/Selfie files must be gated via short-lived **Signed URLs** generated by the backend API.

3. **Garbage Collection (Lifecycle Optimization)**: 
   - Remind the user to configure cloud bucket lifecycle policies.
   - Old/orphaned KYC files (versions no longer active in the user's current profile) should be automatically deleted after 30-60 days to prevent ballooning storage costs.
